# Working process

Start by reading the user's request, repository instructions and current changes.
Keep other people's edits. When several agents share a checkout, agree on file
ownership before editing. Use the host's permissions and available tools.

Choose the smallest change that completes the request. Ask for missing information
only when it changes what can be done safely or correctly. Keep publication and
account actions within the user's authorization. A deploy is a private preview;
public release needs its own approval.

Use the user's time, spend and reporting limits. Set a bounded checkpoint before
starting uncertain research or a paid call. Stop at that checkpoint and report the
result. Do not invent permission, credentials, a budget or tools that are absent.

Inspect the result through the player's route. Keep evidence of input, state changes
and the frame the player sees. Run relevant checks in sequence. A changed check
needs a deliberate failing case before its passing result is useful.

Ask an independent reviewer to examine the result when the host permits delegation.
Give them the running artifact and its acceptance criteria. If independent review
is unavailable, say so and review the diff separately from the implementation.

Report what changed, what was observed and what remains uncertain. State blocked
work and the next useful action. Continue within the agreed scope; do not repeat
unchanged checks or start another polish pass without a concrete gap.

Keep public packages free of credentials, personal data and private transcripts.
Publish distilled lessons and synthetic examples. Inspect the packed files as well
as the source before releasing them.

## Long builds with feedback rounds

When a game is built over many rounds of the owner's feedback, most lost rounds have
process causes. OG Clash took about 190 numbered builds to reach its final game. Read
`opengame-production` before the first build: it covers the bar file written in the
first hour, the ask register, one integrator, frozen rounds with receipts, the latest
playable address, usage limits, machine load and status updates.
